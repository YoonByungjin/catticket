# 0012. メールは専用の Gmail アカウントから SMTP（アプリパスワード）で送る

- 日付: 2026-11-05
- 状態: 提案
- 関係する要件: F-12 ⑥, F-14 ④(a), F-15 ①, N-07（U-21、7.3 の申し送り）

## 背景

- メールを使うのは、会員登録の認証（F-12 ⑥）、ロック解除のためのメールアドレスの再認証（F-14 ④(a)）、パスワード再設定（F-15 ①）の3つ（U-21）。
- 人間の決定 T-02: **このプロジェクト専用の Gmail アカウントを新しく作って使う**（個人のメールとは分ける）。
- 月0円（N-07）。ドメインは DuckDNS のサブドメイン（0010）で、メールのための DNS レコード（SPF・DKIM など）を自由に設定できない。
- サーバーは Oracle Cloud。2021 年 6 月以降に作ったテナンシーは、外向きの 25 番ポートが止められている。

## 決定

1. メールは**専用の Gmail アカウントから、Gmail の SMTP サーバー（`smtp.gmail.com`、587 番ポート・STARTTLS）**で送る。送信元のアドレスはその Gmail アドレスにする。
2. 認証は**アプリパスワード**を使う。専用アカウントで2段階認証を有効にしてから、アプリパスワードを作る。アプリパスワードはサーバーの環境変数（`.env`）にだけ置く。
3. Spring Boot の **`spring-boot-starter-mail`（`JavaMailSender`）** を使う。これは新しいライブラリの追加であり、この ADR の採用をもって導入を認める。
   - タイムアウトを必ず設定する（既定では無限で、スレッドが止まるおそれがある。公式）。値は 06 で決める。
4. **使用量の上限（T-01 に準じる）**: Gmail の個人アカウントは1日 500 通（受信者 500 人）を超えると送信が止まる（公式）。アプリ側で**1日 400 通**を上限にし、超えた分は送らずエラーにする（Gmail の制限に当たって他のメールまで止まるのを避ける）。
5. 送信に失敗したときの画面の動き・再送の扱いは、要件の範囲で 02・03 で決める（要件にない「再送」の機能は足さない）。

## 検討した選択肢

| 選択肢 | 無料の範囲 | カード | 判断 |
|---|---|---|---|
| **Gmail の SMTP（アプリパスワード）** | 1日 500 通まで | 不要 | **採用を提案。** T-02 のとおり専用 Gmail を使え、DNS の設定がいらない。送信量（登録・再認証・再設定）は少ない |
| Gmail API（OAuth 2.0。SMTP の XOAUTH2 を含む） | 同じ | 不要 | Google が勧める方式だが、OAuth の同意画面が「テスト」の状態だと更新トークンが 7 日で切れる（公式）。公開するには送信の権限の審査が必要になり、運用の負担が大きい |
| メール配信サービス（無料プランのあるもの） | サービスによる | サービスによる | 多くは送信元ドメインの DNS 認証（SPF・DKIM）を求める。DuckDNS では自由にレコードを作れない。T-02（専用 Gmail）とも合わない |
| サーバーから直接送る（自前のメールサーバー） | — | — | OCI は 25 番ポートを止めている。迷惑メール扱いになりやすい |
| Oracle Cloud の Email Delivery | — | — | 送信元ドメインの認証が必要で、DuckDNS では難しい。T-02 と合わない |

## 結果（良い点・注意点）

### 費用（月0円の範囲か）

| 項目 | 内容 |
|---|---|
| 無料枠 | Gmail（個人アカウント）: 1日 500 通・1通の受信者 500 人まで |
| カード登録 | 不要 |
| 上限を超えたとき | 送信が止まる（通常 1〜24 時間で戻る）。課金はない |
| 上限・アラートの設定 | 課金がないため予算アラートは不要。アプリ側で1日 400 通を上限にし、上限に達したことをログに残す |

### 良い点

- 費用がかからず、カードもいらない。DNS の設定もいらない。
- Gmail から Gmail などへの到達がよい。

### 注意点

- Google はアプリパスワードを「推奨しない」としている（公式）。2段階認証をセキュリティキーだけにした場合や、高度な保護機能を使う場合は、アプリパスワードを作れない。専用アカウントではそれらを使わない。
- アプリパスワードが漏れるとアカウントのメールを送られてしまう。`.env` にだけ置き、Git に入れない。漏れたら取り消して作り直す。
- 宛先が無効でメールが多く戻ってくると、約 24 時間送信が制限されることがある（公式）。
- OCI の 587 番ポートは止められていない（Oracle のサポート文書。検索結果で確認）。サーバーを作ったときに実際に送れるか確かめる。
- メール本文のリンクは本番の URL（0010）を使う。

### 確認した公式ドキュメント（確認日: 2026-11-05）

- Gmail の送信の上限（1日 500 通、止まったときの戻り方、戻りメールが多いときの制限）: https://support.google.com/mail/answer/22839
- アプリパスワード（2段階認証が必要、推奨しない、作れない場合）: https://support.google.com/accounts/answer/185833
- Gmail の SMTP（`smtp.gmail.com`、465・587 番、SASL）: https://developers.google.com/workspace/gmail/imap/imap-smtp
- OAuth 2.0（「テスト」状態の更新トークンは 7 日で切れる）: https://developers.google.com/identity/protocols/oauth2
- Spring Boot のメール（`spring-boot-starter-mail`、`spring.mail.*`、タイムアウトの設定）: https://docs.spring.io/spring-boot/reference/io/email.html
- OCI の外向き SMTP の制限: https://docs.oracle.com/en-us/iaas/releasenotes/changes/f7e95770-9844-43db-916c-6ccbaf2cfe24 （検索結果で確認。587・465 番を止めない旨は My Oracle Support の文書 2787393.1 による）

## 한국어

### 0012. 메일은 전용 Gmail 계정에서 SMTP(앱 비밀번호)로 보낸다

- 날짜: 2026-11-05
- 상태: 제안
- 관련 요건: F-12 ⑥, F-14 ④(a), F-15 ①, N-07 (U-21, 7.3 인계)

### 배경

- 메일을 쓰는 곳은 회원가입 인증(F-12 ⑥), 잠금 해제를 위한 이메일 재인증(F-14 ④(a)), 비밀번호 재설정(F-15 ①) 3가지(U-21).
- 사람의 결정 T-02: **이 프로젝트 전용 Gmail 계정을 새로 만들어 쓴다**(개인 메일과 분리).
- 월 0원(N-07). 도메인은 DuckDNS 서브도메인(0010)이라 메일용 DNS 레코드(SPF·DKIM 등)를 자유롭게 설정할 수 없다.
- 서버는 Oracle Cloud. 2021년 6월 이후 만든 테넌시는 외부 25번 포트가 막혀 있다.

### 결정

1. 메일은 **전용 Gmail 계정에서 Gmail SMTP 서버(`smtp.gmail.com`, 587번 포트·STARTTLS)**로 보낸다. 보내는 주소는 그 Gmail 주소로 한다.
2. 인증은 **앱 비밀번호**를 쓴다. 전용 계정에서 2단계 인증을 켠 뒤 앱 비밀번호를 만든다. 앱 비밀번호는 서버 환경변수(`.env`)에만 둔다.
3. Spring Boot의 **`spring-boot-starter-mail`(`JavaMailSender`)**을 쓴다. 새 라이브러리 추가이며, 이 ADR의 채택으로 도입을 허용한다.
   - 타임아웃을 반드시 설정한다(기본값은 무한이라 스레드가 멈출 수 있다. 공식). 값은 06에서 정한다.
4. **사용량 상한(T-01에 준함)**: Gmail 개인 계정은 하루 500통(수신자 500명)을 넘으면 발송이 멈춘다(공식). 앱에서 **하루 400통**을 상한으로 하고, 넘는 것은 보내지 않고 오류로 한다(Gmail 제한에 걸려 다른 메일까지 멈추는 것을 피한다).
5. 발송에 실패했을 때의 화면 동작·재발송 처리는 요건 범위 안에서 02·03에서 정한다(요건에 없는 "재발송" 기능은 더하지 않는다).

### 검토한 선택지

| 선택지 | 무료 범위 | 카드 | 판단 |
|---|---|---|---|
| **Gmail SMTP(앱 비밀번호)** | 하루 500통까지 | 불필요 | **채택 제안.** T-02대로 전용 Gmail을 쓸 수 있고 DNS 설정이 필요 없다. 발송량(가입·재인증·재설정)은 적다 |
| Gmail API(OAuth 2.0. SMTP XOAUTH2 포함) | 같음 | 불필요 | Google이 권하는 방식이지만, OAuth 동의 화면이 "테스트" 상태면 갱신 토큰이 7일 만에 만료된다(공식). 공개하려면 발송 권한 심사가 필요해 운영 부담이 크다 |
| 메일 발송 서비스(무료 플랜이 있는 것) | 서비스마다 다름 | 서비스마다 다름 | 대부분 보내는 도메인의 DNS 인증(SPF·DKIM)을 요구한다. DuckDNS에서는 레코드를 자유롭게 만들 수 없다. T-02(전용 Gmail)와도 맞지 않는다 |
| 서버에서 직접 발송(자체 메일 서버) | — | — | OCI는 25번 포트를 막는다. 스팸으로 분류되기 쉽다 |
| Oracle Cloud Email Delivery | — | — | 보내는 도메인 인증이 필요해 DuckDNS로는 어렵다. T-02와 맞지 않는다 |

### 결과 (좋은 점·주의점)

#### 비용 (월 0원 범위인가)

| 항목 | 내용 |
|---|---|
| 무료 한도 | Gmail(개인 계정): 하루 500통·메일 1통 수신자 500명까지 |
| 카드 등록 | 불필요 |
| 한도를 넘었을 때 | 발송이 멈춘다(보통 1~24시간 뒤 돌아옴). 과금은 없다 |
| 상한·알림 설정 | 과금이 없으므로 예산 알림은 불필요. 앱에서 하루 400통을 상한으로 하고, 상한에 이른 것을 로그에 남긴다 |

#### 좋은 점

- 비용이 들지 않고 카드도 필요 없다. DNS 설정도 필요 없다.
- Gmail에서 Gmail 등으로의 도달이 좋다.

#### 주의점

- Google은 앱 비밀번호를 "권장하지 않는다"고 한다(공식). 2단계 인증을 보안 키만으로 했거나 고급 보호 기능을 쓰면 앱 비밀번호를 만들 수 없다. 전용 계정에서는 그것들을 쓰지 않는다.
- 앱 비밀번호가 새면 계정 메일이 발송될 수 있다. `.env`에만 두고 Git에 넣지 않는다. 새면 취소하고 다시 만든다.
- 수신 주소가 무효라 메일이 많이 되돌아오면 약 24시간 발송이 제한될 수 있다(공식).
- OCI의 587번 포트는 막혀 있지 않다(Oracle 지원 문서. 검색 결과로 확인). 서버를 만들 때 실제로 보낼 수 있는지 확인한다.
- 메일 본문의 링크는 운영 URL(0010)을 쓴다.

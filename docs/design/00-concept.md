## 1. 背景・課題

ソウルに住む韓国人が公演を探すとき、次の4つに困っている（Q-01, Q-02）。

1. 近くで何をやっているか分からない。
2. 日時・場所で絞り込みにくい。
3. 会場周辺の情報（コインロッカー・公共交通（最寄り駅））がない。駐車場は周辺情報に含めない（データの入手が難しいため）。
4. 何が面白いのか（人気・評判）を判断しにくい。

## 8. 要件定義・設計への申し送り

**決定ではなく引き継ぎ。** この企画書では技術・API・画面を決めていない。

- **画面の構想（人間のアイデア、追加分1）**: 最初の画面は地図にすべての公演をピンで表示する。ピンを押すと、その周辺 500m の駅・コインロッカーを表示する。「近くを見る」ボタンを押すと、GPS で自分の位置から 500m の公演・コインロッカー・駅を表示する。→ 画面設計（02）で具体化する。
- **技術の希望（ADR で判断する、追加分1）**: 地図は Google マップ API を使いたい（ADR 0004）。翻訳 API は未定（新しい ADR）。いずれも運用コスト月0円（無料の範囲内でのみ運用する。U-02, 追加分4 U-12）の範囲内で選ぶ。→ 未決事項 U-14
- **デプロイ（追加分1、追加分3 U-12 補足）**: ドメイン（DNS）を取得して公開する。すでに使っているサーバーはなく、ドメインもまだない。
- **技術の希望（ADR で判断する、追加分3）**: サーバーは Oracle Cloud の無料枠（長く無料で使えるため）、ドメインは DuckDNS の無料ドメイン。決定ではない。→ 未決事項 U-22
- **サーバーの制約の値（追加分4 の申し送り）**: メモリなどサーバーの制約の値は、サーバーの選択（U-22、ADR）が決まったらその仕様に従う。U-22 とともに基本設計（ADR）で決める。→ 未決事項 U-22
- **コインロッカーの位置データ（追加分3 U-16）**: 人間が持っている `locker_lat_lng.csv` を候補とする（採用は決定していない）。リニューアル前のプロジェクトで使っていたデータで、公共データポータル（ソウル交通公社のデータと推定）から取得し、人間が自分で前処理・加工したもの。
  - **CSV の実際の状態（実行 Claude が確認した事実、追加分3）**: 316行、駅は 227 か所（うち1か所は京畿道高陽市の紙杻（チチュク）駅・3号線。この駅のコインロッカーは追加分4 U-23 で扱わないと決定。X-13）。座標はコインロッカーではなく**駅の座標**で、コインロッカーの位置は「1番出入口付近」のような文章でしかない。完全に重複した行が 13 行ある。出典・基準日・ライセンスの情報はファイルにない。現在 git には入っていない。→ 未決事項 U-20
  - 出典・ライセンス（公共ヌリの類型など）を確認する。→ 未決事項 U-19。リポジトリのどこに置くか、重複の除去などの整理は設計で決める。
- **「駅」の位置データは別に必要（追加分3）**: CSV にはコインロッカーのある駅しかないため、「500m 以内の駅」を表示するには、すべての駅の位置データの出どころを決める必要がある。→ 未決事項 U-18
- **メール送信（追加分3）**: 一般ユーザーの登録・ログインはメールアドレス・パスワード方式（U-17）。メール送信を何に使うか（登録時の認証、パスワード再設定など）は要件定義で決め、メールの送信方法は ADR で判断する。→ 未決事項 U-21
- **レビュー削除（追加分1）**: レビュー機能を入れるので、管理者によるレビュー削除などが必要かは要件定義で扱う。→ 未決事項 U-11
- **翻訳の品質と費用（追加分1、追加分4 U-12）**: 固有名詞（公演名・会場名）の機械翻訳の品質は要件定義・ADR で扱う。翻訳 API の費用は運用コスト月0円の範囲内に収める。→ 未決事項 U-13
- **データの出どころ（追加分2。PM が KOPIS 開発ガイド v5.0 で確認した事実。採用は ADR で判断）**: → 未決事項 U-15
  - S-01: 予約状況（`boxoffice`）。期間・ジャンル（`catecode`）・地域（`area=11` ソウル）で絞れ、応答に順位（`rnum`）と公演 ID（`mt20id`）がある
  - S-02: KOPIS に評価・レビューのデータはないため、自分たちのレビューで作る
  - S-03: 受賞作一覧（`prfawad`）の `awards`
  - S-04: 公演一覧の `openrun`、公演別統計（`prfstsPrfBy`）の上演回数（`prfdtcnt`）
  - S-05: KOPIS に「急上昇」はない。S-01 の順位を自分たちで毎日保存し、変化を計算する必要がある
  - S-06: ジャンル別予約統計（`boxStatsCate`）。ジャンル単位の予約数・販売額
- **できないこと（追加分2）**: KOPIS は**公演ごとの販売数を提供していない**（公演単位は順位と上演回数まで。販売数はジャンル・会場単位の合計のみ）。ペルソナの「どれがよく売れているか」は順位で表す。
- **範囲の拡大と期限（Q-08、追加分2）**: 範囲がさらに広がったため、要件定義で Must / Should を付け、工程ごとの見積もりで Q-08 の期限との差を確認する。→ 未決事項 U-10

X-02는 결번(이전 판의 "기한에 맞추지 못할 때 범위를 줄이는 것"은 "안 하는 것"에서 빼고 성공 기준 G-02에만 남겼다).

구체적인 기능·우선순위(Must / Should / Could)·완료 기준은 요건정의(공정 2)에서 정한다. 기술·외부 API·화면의 구체적인 내용은 기본설계 이후에 다룬다.

### 7. 미결 사항

### 8. 요건정의·설계로 넘기는 사항

**결정이 아니라 인계.** 이 기획서에서는 기술·API·화면을 정하지 않았다.

- **화면 구상(사람의 아이디어, 추가분1)**: 첫 화면은 지도에 모든 공연을 핀으로 표시한다. 핀을 누르면 그 주변 500m의 역·보관함을 보여준다. "근처 둘러보기" 버튼을 누르면 GPS로 내 위치 기준 500m의 공연·보관함·역을 보여준다. → 화면설계(02)에서 구체화한다.
- **기술 희망(ADR로 판단, 추가분1)**: 지도는 Google 지도 API를 쓰고 싶다(ADR 0004). 번역 API는 미정(새 ADR). 둘 다 운영 비용 월 0원(무료 범위 안에서만 운영. U-02, 추가분4 U-12) 범위 안에서 고른다. → 미결 사항 U-14
- **배포(추가분1, 추가분3 U-12 보충)**: 도메인(DNS)을 받아서 공개한다. 이미 쓰고 있는 서버는 없고, 도메인도 아직 없다.
- **기술 희망(ADR로 판단, 추가분3)**: 서버는 Oracle Cloud 프리티어(오래 무료로 쓸 수 있으므로), 도메인은 DuckDNS 무료 도메인. 결정이 아니다. → 미결 사항 U-22
- **서버 제약의 값(추가분4 인계)**: 메모리 등 서버 제약의 값은 서버 선택(U-22, ADR)이 정해지면 그 사양에 따른다. U-22와 함께 기본설계(ADR)에서 정한다. → 미결 사항 U-22
- **보관함 위치 데이터(추가분3 U-16)**: 사람이 가진 `locker_lat_lng.csv`를 후보로 한다(채택은 결정되지 않음). 리뉴얼 전 프로젝트에서 쓰던 데이터로, 공공데이터포털(서울교통공사 데이터로 추정)에서 받아 사람이 직접 전처리·가공한 것.
  - **CSV의 실제 상태(실행 Claude가 확인한 사실, 추가분3)**: 316행, 역 227곳(1곳은 경기 고양 지축역·3호선. 이 역의 보관함은 추가분4 U-23에서 다루지 않기로 결정. X-13). 좌표는 보관함이 아니라 **역의 좌표**이고 보관함 위치는 "1번 출입구 주변" 같은 글로만 있다. 완전 중복 행 13개. 출처·기준일·라이선스 정보는 파일에 없다. 현재 git에 올라가 있지 않다. → 미결 사항 U-20
  - 출처·라이선스(공공누리 유형 등)를 확인한다. → 미결 사항 U-19. 저장소 어디에 둘지, 중복 제거 등 정리는 설계에서 정한다.
- **"역" 위치 데이터는 따로 필요(추가분3)**: CSV에는 보관함이 있는 역만 있으므로, "500m 안의 역"을 보여주려면 모든 역의 위치 데이터 출처를 정해야 한다. → 미결 사항 U-18
- **메일 발송(추가분3)**: 일반 사용자의 가입·로그인은 이메일·비밀번호 방식(U-17). 메일 발송을 무엇에 쓸지(가입 인증, 비밀번호 재설정 등)는 요건정의에서 정하고, 메일 발송 방법은 ADR에서 판단한다. → 미결 사항 U-21
- **리뷰 삭제(추가분1)**: 리뷰 기능을 넣으므로 관리자의 리뷰 삭제 등이 필요한지 요건정의에서 다룬다. → 미결 사항 U-11
- **번역 품질과 비용(추가분1, 추가분4 U-12)**: 고유명사(공연명·공연장명)의 기계 번역 품질은 요건정의·ADR에서 다룬다. 번역 API 비용은 운영 비용 월 0원 범위 안에 둔다. → 미결 사항 U-13
- **데이터 출처(추가분2. PM이 KOPIS 개발가이드 v5.0에서 확인한 사실. 채택은 ADR에서 판단)**: → 미결 사항 U-15
  - S-01: 예매상황판(`boxoffice`). 기간·장르(`catecode`)·지역(`area=11` 서울)으로 거를 수 있고, 응답에 순위(`rnum`)와 공연 ID(`mt20id`)가 있다
  - S-02: KOPIS에 평점·후기 데이터가 없으므로 우리 리뷰로 만든다
  - S-03: 수상작 목록(`prfawad`)의 `awards`
  - S-04: 공연 목록의 `openrun`, 공연별 통계(`prfstsPrfBy`)의 상연 횟수(`prfdtcnt`)
  - S-05: KOPIS에 "급상승"은 없다. S-01의 순위를 우리가 매일 저장하고 변화를 계산해야 한다
  - S-06: 장르별 예매통계(`boxStatsCate`). 장르 단위 예매수·판매액
- **안 되는 것(추가분2)**: KOPIS는 **공연별 판매 수를 제공하지 않는다**(공연 단위는 순위와 상연 횟수까지. 판매 수는 장르·공연장 단위 합계뿐). 페르소나의 "어느 게 잘 팔리는지"는 순위로 보여준다.
- **범위 확대와 기한(Q-08, 추가분2)**: 범위가 더 넓어졌으므로, 요건정의에서 Must/Should를 붙이고 공정별 예상 일정으로 Q-08 기한과의 차이를 확인한다. → 미결 사항 U-10

# 設計書

実装の正（Single Source of Truth）。上から順に決め、前の工程が変わったら後ろの設計書も見直す。
工程・ゲート・担当エージェントは `CLAUDE.md` の「開発プロセス」を参照。
工程3は番号順ではなく、`02`・`03`・`05` → `07`（試作は `mockups/`）→ `04` の順に作る。

## 한국어

구현의 기준(Single Source of Truth). 위에서부터 순서대로 정하고, 앞 공정이 바뀌면 뒤 설계서도 다시 검토한다. 공정·관문·담당 에이전트는 `CLAUDE.md`의 "개발 프로세스" 참고.
공정 3은 번호 순서가 아니라 `02`·`03`·`05` → `07`(시안은 `mockups/`) → `04` 순서로 만든다.

| No. | 설계서 | 공정 | 담당 | 정하는 것 | 상태 |
|---|---|---|---|---|---|
| 00 | 기획서 | 1 기획 | requirements-analyst | 누구의 어떤 문제를 푸는지, 제공 가치, 범위 | 승인 |
| 01 | 요건정의서 | 2 요건정의 | requirements-analyst | 기능 요건(우선순위·완료 기준), 비기능 요건, 대상 외 | 승인 |
| 02 | 화면설계서 | 3 기본설계 | architect | 화면 목록, 각 화면의 항목·조작·전이 | 승인(2026-11-06, Issue #15 코멘트 6678921752. P-01~P-18은 결정 완료) |
| 03 | API 설계서 | 3~4 기본설계·상세설계 | architect | 엔드포인트, 요청·응답, 오류 | 기본설계: 승인(2026-11-06, Issue #15 코멘트 6678921752. 상세는 공정 4) |
| 04 | 테이블 설계서 | 3~4 기본설계·상세설계 | db-designer | ER 다이어그램, 테이블 정의, 인덱스 | 기본설계: 리뷰 대기(테이블 정의 상세·Flyway는 공정 4) |
| 05 | 배치 설계서 | 3 기본설계 | architect | 정기 처리, 외부 데이터 수집 | 승인(2026-11-06, Issue #15 코멘트 6678921752) |
| 06 | 클래스 설계서 | 4 상세설계 | architect | 패키지, 클래스와 주요 메서드, 예외 처리 | 미착수 |
| 07 | UI 디자인 가이드 | 3 기본설계 | ui-designer | 색·글자·여백 등 토큰, 화면별 시안(`mockups/`)과의 대응 | 리뷰 대기(시안 7개는 사람이 승인함. Issue #15 코멘트 6676583842) |

테스트는 `docs/test/`(공정 6, qa-engineer), 운영 절차는 `docs/ops/`(공정 7, 실행 Claude)에 둔다.
